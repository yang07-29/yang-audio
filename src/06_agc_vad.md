## A AGC 为什么需要动态控制
用户与麦克风的距离改变，说话音量也会改变。自动增益控制 AGC 估计当前电平，再调整增益，使输出保持在合适范围。

简化目标增益为：

$$
g=\frac{R_{\mathrm{target}}}{R_{\mathrm{current}}+\varepsilon}
$$

$R_{\mathrm{target}}$ 和 $R_{\mathrm{current}}$ 分别是目标与当前的非负 RMS 电平，单位相同；$\varepsilon>0$ 用于避免静音附近除零。这只是起点，实际还要增益限幅、平滑、语音活动判断与峰值保护。

AGC 不会凭空改善 SNR：把语音和噪声一起乘二，二者功率比保持不变。静音时盲目提升增益，反而会把底噪拉上来。

## B 起控、释放、压缩与限幅
| 模块 | 作用 | 过度使用的后果 |
|---|---|---|
| 电平检测 | 估计短时 RMS 或峰值 | 太短会跟随波形抖动 |
| 起控时间 | 控制强声音出现时的响应速度 | 太慢可能冲过峰值 |
| 释放时间 | 控制增益恢复速度 | 太快产生抽吸与音量起伏 |
| 压缩器 | 缩小动态范围 | 可能失去自然强弱变化 |
| 限幅器 | 防止过大峰值 | 削波式处理会产生失真 |

峰值、RMS、响度不是同一件事。LUFS 等响度指标更考虑听觉与时间统计，但不能只凭一个响度数字评价语音质量。

## C VAD 是判断有没有人说话
语音活动检测 VAD 通常输出每帧语音概率或语音片段。能量阈值方法简单，但音乐、风声、碰撞声也可能很响。

```flow LR
音频帧 -> 活动概率: 能量或神经网络
活动概率 -> 阈值与迟滞: 减少反复切换
阈值与迟滞 -> 语音片段: 起点、终点与保留边界
```

起始阈值与结束阈值可以不同。保留少量前导和尾部缓冲，可减少切掉首字、尾音的风险。端点检测还要判断一句话是否结束，不完全等同于逐帧 VAD。

## D 唤醒词识别和轮次控制
关键词唤醒 KWS 判断“是否说了指定短语”。它既不同于通用 ASR，也不同于 VAD。VAD 认为有人说话，不等于说了唤醒词。

| 问题 | 指标或现象 |
|---|---|
| 没说唤醒词却触发 | 每小时误唤醒次数 |
| 说了唤醒词没有触发 | 漏检率或拒识率 |
| 噪声环境下首字丢失 | 端点与缓冲策略 |
| 用户停顿时系统抢答 | 轮次结束判断过早 |

阈值要在开发集上选定，不能在最终测试集上反复调到最好。真实背景数据时长影响误唤醒估计可信度。

## E 模块怎样相互影响
AEC、NS、AGC、VAD 的顺序与协同由系统决定，不存在适合所有设备的固定排列。增益突变可能影响其他模块的统计假设，VAD 误判也会影响噪声跟踪。

动手：对同一句话加入音量渐变和噪声。实现慢速增益平滑，比较有无静音增益限制的输出。再人工标注十段音频的起止点，检查 VAD 是否截断音节。

## F 自测与答案
| 问题 | 答案 |
|---|---|
| AGC 可以替代降噪吗？ | 不能；等比例放大语音与噪声不会改善信噪比 |
| VAD 识别出说了哪几个字吗？ | 不负责；它判断语音活动 |
| 更低唤醒阈值一定更好？ | 不一定；漏检可能减少，误触发可能增加 |

## 三个模块回答三个问题
| 模块 | 回答 |
|---|---|
| 自动增益 | 声音是不是太大或太小 |
| 语音活动检测 | 现在有没有人在说话 |
| 关键词唤醒 | 是否说出了指定短语 |
> 自动增益让音量更稳定，但不是降噪。
> 语音活动检测定位说话片段，并不输出完整文字。
> 唤醒模型需要识别特定内容，还要防止误触发。
## 为什么增益要慢慢变
```flow LR
输入电平 -> 目标增益: 比较当前和目标
目标增益 -> 平滑控制: 限制变化速度
平滑控制 -> 输出保护: 防止过载
```
> 当前太轻，就可能需要提高增益。
> 如果跟随每个采样点跳变，声音会不自然。
> 最后还要限制峰值，避免数字削波。
## 端点决定交互体验
| 设置 | 可能后果 |
|---|---|
| 结束等待太短 | 用户停顿被误判为说完 |
| 结束等待太长 | 系统回答迟迟不开始 |
| 边界没有缓冲 | 句首句尾被截断 |
> 端点并不是简单地发现安静就立即结束。
> 需要在响应速度和完整保留语音之间权衡。
> 测试时保留停顿、弱音与背景噪声这些困难样例。
