## A 你应优先投入什么
结合电子信息与水声背景，建议先把增强或阵列做成一个完整主项目，再以领域 ASR 作为第二线。TTS、声纹和语音大模型建立全貌后，按具体岗位继续深入。

这是一项学习投入建议，不是保证录取。招聘中的“熟悉 DSP”“掌握 PyTorch”“有项目经验”，分别需要推导和仿真、训练调试、独立实验记录来证明。

公开样本中，[深圳北科瑞声平台岗位](https://pcyg.globalrecruit.cn/jobs/142)明确涉及阵列、定位、AEC 与仿真；[百度官方语音实习](https://talent.baidu.com/jobs/detail/INTERN/d1e5aeba-8e47-410c-b5f9-d2ca79f955bf)涉及 ASR/TTS、PyTorch 与语音大模型模块。它们支持课程方向划分，但不代表所有岗位要求相同，也不保证当前名额开放。

## B 项目一规格：语音增强与实时性
输入为合法获取的干净语音与噪声，按说话人和噪声来源划分。实现未处理输入、传统基线和一个轻量网络；固定测试集与采样率后比较。

| 交付文件 | 最低内容 | 面试可追问 |
|---|---|---|
| 数据说明 | 来源、数量、时长、划分、许可 | 是否泄漏？是否含静音？ |
| 运行说明 | 环境、命令、配置、随机种子 | 换机器能否复现？ |
| 训练日志 | 损失、验证、检查点选择 | 为什么选这个轮次？ |
| 结果表 | 输入基线、分组指标、时延 | 对未知噪声是否有效？ |
| 失败样例 | 原始、处理后、原因假设 | 有没有吞辅音或尾音？ |

建议先做两项清晰消融，例如相位处理和因果限制。不要一次改网络、数据、损失和评测，再把全部差异归因于某一个创新。

## C 项目二规格：阵列与水声迁移
定义阵列几何、声速、频段与坐标。先在已知条件验证 GCC-PHAT 或 MUSIC，再引入噪声、反射和校准误差。若做波束形成，比较单麦、延迟求和与一种自适应方法。

导师项目可写进简历的前提是你确实参与，能讲出个人贡献，且展示内容符合项目要求。写“水声定位/阵列估计”完全合理；不应把任务改名成没有做过的语音识别。

可迁移证据包括：采集流程、信号预处理、模型假设、定位误差、消融实验与工程实现。合作单位名称不是算法能力的替代品。

## D 面试题库与合格答案要点
| 问题 | 合格回答至少包含 |
|---|---|
| 采样率与频率有什么区别？ | 记录密度与信号振动；举混叠例子 |
| 为什么分帧加窗？ | 非平稳信号局部分析；泄漏与分辨权衡 |
| NLMS 比 LMS 多了什么？ | 用输入能量归一化更新；仍需控制步长 |
| 双讲怎样影响 AEC？ | 误差含近端，可能污染更新；保护近端 |
| 降噪后识别变差怎么办？ | 检查语音损伤、训练失配与业务指标 |
| GCC-PHAT 的峰为什么错？ | 混响、周期性、低带宽、几何与同步 |
| MUSIC 需要哪些假设？ | 阵列模型、源数、子空间和协方差质量 |
| CTC 为什么需要空白？ | 对齐及重复字符；折叠顺序 |
| CER 如何统计？ | $\mathrm{CER}=\frac{N_{\mathrm{edit}}}{N_{\mathrm{ref}}}$，固定归一化 |
| 时长展开和声码器各做什么？ | 时间对齐与波形生成；形状关系 |
| 声纹阈值如何选？ | 开发集、FAR/FRR、业务工作点 |
| RTF 为什么不够？ | 首包、排队、未来等待与端到端时延 |

表中 $N_{\mathrm{edit}}$ 是替换、删除和插入的总次数，$N_{\mathrm{ref}}>0$ 是总参考字数；零参考情况按实战09的规则单列处理。回答时要举自己实际实验中的例子，而不是只复述术语。无法回答时，回到对应实战章做一次改错实验。

## E 分阶段学习验收
| 阶段 | 建议用时 | 完成证据 | 不通过时怎么补 |
|---|---|---|---|
| 基础数据 | 1—2 周 | 实战 01 的独立重建和 SNR 实验 | 先补数组与采样概念 |
| 训练基础 | 1—2 周 | 实战 02 可改动、可定位错误 | 做小数据过拟合与形状检查 |
| 主线算法 | 3—5 周 | AEC/增强/阵列至少一个消融报告 | 缩小任务，先复现基线 |
| 项目完善 | 3—5 周 | 真实数据、失败样例、性能表 | 先固定测试协议再换模型 |
| 投递准备 | 持续 | 一页简历、两分钟讲述、模拟面试 | 按真实岗位补缺口 |

时间按每周约 10—15 小时估计，会随编程基础和课业变化。2027 年春季就应开始查看并尝试暑期岗位，不必等到 7 月才启动投递。

## F 简历写法与边界
模板：“针对【问题】，基于【实际数据与划分】实现【方法】；与【基线】在【固定条件】比较【实测结果】；负责【个人工作】，分析【失败与限制】。”

本课程合成实验可以写为学习或课程实验，不能包装成真实公司业务落地。把合成数据替换为合规真实语料、补齐评测与对照后，才形成更有说服力的独立项目。

投递验收：你能不看稿讲清一个完整项目；能现场解释或修改一段核心代码；能证明结果来自固定测试；能诚实说明未做过的部分。这比把所有缩写都列进技能栏更有用。
