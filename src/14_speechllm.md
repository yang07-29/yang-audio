## A 先区分三种编码
| 名称 | 目的 | 输出 |
|---|---|---|
| PCM 等采样编码 | 数字化记录 | 采样值 |
| 音频压缩编码 | 降低存储与传输码率 | 比特流 |
| 神经音频表示或单元 | 重建、理解或生成建模 | 连续向量或离散单元 |

一个“编码器”可能是 ASR 的特征网络，也可能是音频压缩器。要看它的训练目标和输出用途。

码率与采样率不是一回事。一个系统可以用高采样率波形，但用较低比特率传输。

## B 神经编解码器与离散单元
```flow LR
音频波形 -> 编码器: 压缩时间表示
编码器 -> 向量量化: 映射到码本索引
向量量化 -> 解码器: 重建波形
```

残差向量量化 RVQ 用多级码本逐步表示剩余误差。码本数、码本大小、每秒帧数影响码率。若每帧使用 $Q$ 个码本，每个索引都用 $b$ 比特定长编码，则原始索引码率为：

$$
R=f_{\mathrm{frame}}\,Q\,b
$$

其中 $f_{\mathrm{frame}}$ 是每秒帧数，$R$ 的单位是 bit/s。这个示意式不包含额外封装与熵编码影响；若各码本的索引位数不同，应逐码本相加，不能直接使用同一个 $b$。

语义单元倾向表达内容，声学单元倾向保留重建所需细节，但二者并非绝对隔离。应通过任务与实验判断表示包含什么。

EnCodec 是神经音频编码的开源例子，见[作者仓库](https://github.com/facebookresearch/encodec)。它帮助理解编解码流程，不代表所有语音大模型使用同一种编码器。

## C 级联与端到端系统
| 路线 | 流程 | 主要取舍 |
|---|---|---|
| 级联语音助手 | ASR → 语言模型 → TTS | 模块清楚、便于调试；错误与时延会传递 |
| 音频理解模型 | 音频编码器 → 对齐模块 → 语言模型 | 可以利用非文本声音线索；需对齐训练 |
| 语音到语音模型 | 音频条件 → 文本或音频单元 → 语音 | 保留表达线索；训练和评价更复杂 |

有些模型显式生成中间文字，有些交错生成，有些直接生成音频表示。不能仅凭“端到端”三个字推断内部结构或低延迟能力。

## D 训练与适配要学什么
先理解 Transformer、自回归预测、序列掩码与缓存，再学习音频—文本对齐、指令微调与参数高效适配。

SFT 用示范数据学习目标行为；偏好优化利用相对偏好；强化学习还涉及奖励、采样和策略优化。它们是进阶能力，不是零基础第一周的任务。

音频与文字采样时间尺度不同。下采样过强可能丢失细节，序列过长则消耗显存与时延。任务需要在信息量与计算量间取舍。

## E 全双工不等于同时开两个线程
全双工交互允许系统说话时继续听用户。系统需要处理自身扬声器回声、用户插话、生成取消、缓存清理和轮次切换。

| 能力 | 测什么 |
|---|---|
| 内容理解 | 正确回答、领域事实与指令遵循 |
| 语音表达 | 读音、自然度、音色与情绪条件 |
| 轮次控制 | 是否抢答、是否拖延、是否正确让出话语权 |
| 打断响应 | 从用户打断到停止播放的时间 |
| 稳定性 | 网络抖动、长对话、连续并发 |

如果回声消除失败，系统可能把自己说的话当作用户输入，产生自激式对话。前端与大模型需要协同。

## F 入门项目与自测
先做级联系统：固定 ASR 与 TTS，测端点、生成和播放链路。再只替换一个模块比较收益。项目贡献可以是严格评测、时延优化或领域适配，不一定是训练最大模型。

| 问题 | 答案 |
|---|---|
| 音频 token 就是文字 token 吗？ | 不是；它可能表示声学、语义或混合信息 |
| 级联系统一定比端到端差吗？ | 不一定；要比较数据、任务、时延与可控性 |
| 全双工为什么仍需要 AEC？ | 系统自己的播放声音也会进入麦克风 |

## 一条容易理解的链路
```flow LR
用户语音 -> 语音识别: 得到文字
语音识别 -> 语言模型: 理解并生成回答
语言模型 -> 语音合成: 把回答说出来
```
> 级联系统先把声音转成文字。
> 语言模型依据文字与上下文决定回答。
> 合成模型再把回答变成音频。
## 更直接的音频建模
| 模块 | 作用 |
|---|---|
| 音频编码器 | 把波形压成表示 |
| 对齐与生成模型 | 连接音频、文字和上下文 |
| 音频解码器 | 把表示变回声音 |
> 音频表示能保留一些文字转写之外的信息。
> 但不同模型保留的信息并不相同。
> 编码、对齐和解码方式都要通过结构与实验确认。
## 能被打断，才像自然对话
| 情况 | 系统动作 |
|---|---|
| 自己正在播音 | 继续检测用户语音 |
| 用户插话 | 停止旧回答与播放 |
| 新输入到来 | 更新上下文并重新回应 |
> 全双工系统说话时还要听。
> 它必须识别真实插话，不能把自己的回声当成用户。
> 打断涉及模型、缓存与播放链路，不只是一个按钮。
