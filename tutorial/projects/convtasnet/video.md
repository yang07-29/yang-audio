## A 先听懂任务
```flow LR
两人同时说话 -> 一路混音: 麦克风录下叠加声音
一路混音 -> 分离模型: 输入整段波形
分离模型 -> 两路输出: 每路尽量保留一个人
两路输出 -> 参考语音: 有参考才计算客观分数
```
> 你看，两个人同时讲话，麦克风只录下一路混音。
> [分离模型]要做的是拆开声音，不是把语音转成文字。
> 两路输出只有编号，第一路并不保证一直是同一个人。
> 我们还要用[参考语音]检查效果，不能只看文件是否生成。

## B 看懂模型内部
```flow LR
一路混音 -> 编码器: 学习波形特征
编码器 -> 时间卷积网络: 利用前后文
时间卷积网络 -> 两套掩码: 分配给两名说话人
两套掩码 -> 解码器: 还原两路波形
```
> [编码器]把短波形变成许多特征通道，像换一套坐标观察声音。
> [时间卷积网络]结合前后的线索，猜哪些特征来自同一个人。
> [两套掩码]分别作用于同一份特征，不是直接切走某些频率。
> [解码器]把特征还原成声音。这个版本需要前后文，不是流式模型。

## C 输出顺序为什么可以交换
```flow LR
两路输出 -> 原顺序配对: 输出一对参考一
两路输出 -> 交换配对: 输出二对参考一
原顺序配对 -> 比较整句平均分
交换配对 -> 比较整句平均分
比较整句平均分 -> 选择更好的配对
```
> 模型只知道要输出两个人，却没有被规定第一路必须是谁。
> 如果只认固定顺序，好结果也可能被错判成差结果。
> 所以我们比较[原顺序配对]和交换配对。
> 注意，是整句话保持同一配对，不能每一帧随意换人。
> 选择更好的配对后，再计算损失。这就是两人场景里的 PIT。

## D 微调到底改了什么
```tree
已有预训练模型
  冻结编码器和时间卷积网络
  更新掩码输出层
  更新解码器
  用开发集选择检查点
```
> 你的仓库不是从随机参数开始训练，而是先读取已有权重。
> 大部分网络被冻结，仍然参与计算，但参数不更新。
> [更新掩码输出层]让已有特征换一种分配方式。
> [更新解码器]调整特征如何还原成声音。
> 最后用开发集选择检查点，测试集不能拿来反复挑模型。

## E 后处理不是魔法
```flow LR
两路输出 -> 公共增益: 同比例校准幅度
公共增益 -> 计算残差: 混音减去两路之和
计算残差 -> 分配残差: 等权或按全句能量
分配残差 -> 回到原混音: 两路相加满足约束
```
> [公共增益]对两路一起缩放，不是每一路单独拉到一样响。
> 然后计算两路相加后，还差了多少声音。
> [分配残差]把这部分差额放回两路输出。
> 两路加起来正确，不等于每一路都分对了。噪声也可能被分进去。

## F 如何讲清真实结果
```tree
项目结论
  三个种子完成局部微调
  同后处理下比较微调增量
  主要对照区间跨过零
  保留失败样例与适用边界
```
> 仓库报告记录了三个种子的完整实验，这比只跑一个样例更扎实。
> 但比较必须固定后处理，不能把两种变化混在一起。
> [主要对照区间跨过零]，所以现在不能说微调带来了稳定改善。
> 面试中讲清这个限制，再解释数据划分、失败分析和恢复机制，会更可信。
